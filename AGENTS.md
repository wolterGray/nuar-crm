# NUAR CRM — Архитектурные стандарты и контекст для ИИ

> **Единый источник правды для любых изменений кода и дизайна в CRM.**  
> Все последующие изменения, выполняемые ИИ или разработчиками, **обязаны** следовать стандартам этого документа.  
> **Связь с сайтом и CMS (троица: CRM + админка + сайт)** описана в соседнем репозитории: `../lavandi/AGENTS.md` (или `wolterGray/lavandi/AGENTS.md` на GitHub). Читай его, если задача затрагивает сайт или CMS.

## 1. Что это и системный контекст

**nuar-crm** — внутренняя CRM салона массажа NUAR (Варшава): клиенты, визиты, услуги, сотрудники, касса, статистика, задачи, автоматизация сообщений.

| Параметр | Значение |
|---|---|
| Репозиторий | `wolterGray/nuar-crm` |
| Стек Frontend | React 19 + Vite, Tailwind CSS v4, Lucide Icons (через `AppIcon`) |
| Стек Backend | Node.js / Express API, Prisma ORM + PostgreSQL |
| Деплой | Hetzner VPS: frontend + backend + PostgreSQL (`crm.nuarr.pl`) |
| Тесты и сборка | Vitest (`npm run test`), ESLint (`npm run lint`), Vite (`npm run build`) |

### Связь с сайтом и админкой (`lavandi`)

CRM работает через собственный backend на Hetzner. Сайт и CMS используют общую базу PostgreSQL:

| Компонент | Репозиторий | URL |
|-----------|-------------|-----|
| CRM | `nuar-crm` | Hetzner / `crm.nuarr.pl` |
| Сайт + админка | `lavandi` | https://nuarr.pl, https://nuarr.pl/admin |

- **CRM → сайт (автоматически):** При изменении цен и длительностей услуг в CRM данные пишутся backend-роутами в таблицу `site_content` (`id = 'main'`, поле `data.services`). Задержка ~1.2 с, без кнопок «опубликовать». Админка сайта цены не меняет — только фото и тексты.
- **CRM → админка (SSO):** Страница «Сайт» (`src/components/pages/SitePage.jsx`) с кнопкой «Открыть админку» через CRM auth-flow (`src/utils/openSiteAdmin.js`). Не возвращать старый direct-SDK flow.
- **Backend & База:** `backend/prisma/schema.prisma`, `backend/.env` (секреты Hetzner: `DATABASE_URL`, JWT, SMS/Telegram/Gmail). Frontend общается с backend через `VITE_BACKEND_URL`, прямых запросов в базу из браузера нет.

## 2. Архитектурные принципы дизайн-системы

Дизайн-система CRM Nuar выстроена по строгой четырёхуровневой иерархии:

```
[Уровень 1: Токены]               src/styles/tokens.css, src/design/tokens.css
       │
[Уровень 2: Базовые стили/сбросы] src/index.css (@theme), src/styles/mobile-system.css
       │
[Уровень 3: UI-примитивы]         src/components/ui/* (Button, Input, Badge, Dialog...)
       │
[Уровень 4: Страницы и экраны]    src/components/pages/* (TodayPage, CalendarPage...)
```

### ⭐️ Эталон стиля (Design Benchmark): мобильная страница «Сегодня» (`/today`)

Мобильная страница «Сегодня» (`src/components/pages/TodayPage.jsx`, `TodayPage.module.css`) является **официальным дизайн-референсом и эталоном качества для всего проекта**:
- **Эстетика:** глубокий нейтральный тёмный фон (`#0a0a0a`), сдержанные графитовые карточки (`#141416`, `#1b1b1e`), мягкие тонкие границы (`rgba(255, 255, 255, 0.07)`), акцентный красный NUAR (`#e11d2e`), белый текст с высокой контрастностью.
- **Плотность и ритм:** умеренные паддинги (12–16px), отсутствие визуального мусора, двойных рамок и лишней вложенности.
- **Любые переработки других страниц** (Задачи, Клиенты, Календарь, Финансы, Настройки) должны ориентироваться на эстетику, контраст, типографику и аккуратность экрана `/today`.

## 3. Единая система токенов (Single Source of Truth)

Все стили опираются исключительно на токены.

### Файлы токенов

- **Канонический источник токенов рантайма:** `src/styles/tokens.css`
- **Дизайн-токены и алиасы:** `src/design/tokens.css`
- **Цветовые темы:** `src/styles/color-themes.css` и `src/constants/colorThemes.js`
- **Tailwind v4 интеграция:** `src/index.css` (блок `@theme`)

### Ключевые группы токенов

#### Цвета поверхностей (Surfaces)
- `--bg` / `--color-page`: `#0a0a0a` — основной фон приложения
- `--surface` / `--color-window`: `#141416` — фон основных карточек и панелей
- `--surface-2` / `--color-card-muted`: `#1b1b1e` — приподнятые карточки, списки, ячейки
- `--field` / `--color-field`: `rgba(255, 255, 255, 0.04)` — поля ввода, чипы, вторичные кнопки
- `--color-overlay` / `--modal-backdrop`: `rgba(0, 0, 0, 0.72)` — затемнение модальных окон

#### Цвета текста (Typography Colors)
- `--text` / `--color-text`: `#ffffff` — основной заголовки и важный текст
- `--text-muted` / `--color-text-muted`: `#a4a4ac` — вторичный текст, подписи, иконки
- `--text-faint` / `--color-text-faint`: `#7f7f86` — третичный текст, даты, плейсхолдеры
- Disabled: уменьшенная прозрачность (`opacity: 0.4 - 0.5`)

#### Границы и разделители (Borders)
- `--border` / `--color-border`: `rgba(255, 255, 255, 0.07)` — стандартные границы карточек и контролов
- `--border-soft` / `--color-border-soft`: `rgba(255, 255, 255, 0.045)` — тонкие внутренние разделители
- `--color-border-strong`: `rgba(255, 255, 255, 0.14)` — активные границы при фокусе/наведении

#### Акцентные цвета (Brand Accent)
- `--accent` / `--color-accent` / `--color-primary`: `#e11d2e` — фирменный красный NUAR
- `--accent-hover` / `--color-accent-hover`: `#c91827`
- `--accent-soft` / `--color-accent-soft`: `rgba(225, 29, 46, 0.12)` — мягкий фон активных чипов/статусов

#### Семантические статусы (Status Colors)
- Успех: `--color-success` (`#6fcf97`), `--status-success-bg`, `--status-success-text`
- Предупреждение: `--color-warning` (`#e0a43a`), `--status-warning-bg`, `--status-warning-text`
- Ошибка / Опасность: `--color-error` / `--color-danger` (`#ff4d5e`), `--status-danger-bg`, `--status-danger-text`
- Информация: `--color-info` (`#38bdf8`)
- Премиум: `--color-premium` (`#d1bfa7`)

#### Скругления (Border Radius)
- `--radius-xs`: `4px`
- `--radius-sm`: `6px`
- `--radius-md`: `8px`
- `--radius-control`: `10px` — кнопки, инпуты, селекты
- `--radius-card`: `14px` — карточки и секции
- `--radius-modal`: `16px` — модальные окна, шторки (sheets)
- `--radius-dropdown`: `12px` — выпадающие меню
- `--radius-pill`: `999px` — бейджи, круглые кнопки, аватары

#### Отступы и размеры (Spacing & Sizing)
- Спейсинг: `--space-1` (4px), `--space-2` (8px), `--space-3` (12px), `--space-4` (16px), `--space-5` (20px), `--space-6` (24px), `--space-8` (32px).
- Контролы: `--control-height-sm` (34-38px), `--control-height-md` (40-46px), `--control-height-lg` (46-52px).
- Иконки: `--icon-size-xs` (14px), `--icon-size-sm` (16px), `--icon-size-md` (18px), `--icon-size-lg` (20px), `--icon-size-xl` (24px).

> **ЖЕЛЕЗНОЕ ПРАВИЛО:** Запрещено использовать произвольные hex/rgb-цвета в CSS и инлайн-стилях (`#123456`, `rgb(...)`). Любой цвет должен браться из токенов (`var(--color-...)`) или Tailwind-алиасов.

## 5. Правила мобильной адаптивности

Мобильная система описана в `src/styles/mobile-system.css`, `src/constants/breakpoints.js` и хуке `useBreakpoint`.

### Контрольные точки (Breakpoints)
- **Мобильный экран:** `MOBILE_MAX_WIDTH = 768px` (`@media (max-width: 768px)`).
- **Компактный шелл / планшет:** `SHELL_COMPACT_MAX_WIDTH = 1024px`.
- **Целевой мобильный референс:** ширина **375px – 430px** (базовый эталон — **393 × 852 px**, iPhone 15/16).

### Правила для мобильных интерфейсов
1. **Touch-цели (Touch Targets):**
   - Основные кнопки, поля ввода, селекты, строки списков должны иметь высоту не менее **44–48px** (`--mobile-touch-target: 48px`).
   - Мелкие бейджи, компактные чипы в скролле и иконки действий внутри строк **не должны раздувать шрифты и высоты насильно** (в `mobile-system.css` действует изолированное правило, не ломающее `Badge`, `AppIcon` и чипы).
2. **Безопасные зоны (Safe Area Insets):**
   - Учитывай `env(safe-area-inset-top)` и `env(safe-area-inset-bottom)`.
   - Внизу экрана мобильного шелла находится нижняя навигация `AppNavigation` высотой `--mobile-nav-height: 72px`. Контент страницы всегда должен иметь нижний отступ `--mobile-content-bottom: calc(var(--mobile-nav-total) + 18px)`, чтобы контент не перекрывался баром.
3. **Горизонтальный скролл страницы КАТЕГОРИЧЕСКИ ЗАПРЕЩЁН:**
   - Страница не должна покачиваться или скроллиться по горизонтали (`overflow-x: hidden`).
   - Горизонтальный скролл разрешён **только внутри изолированных блоков** (например, полоса табов `.tabs-scroll-row`, чипы фильтров или широкая таблица с явным `overflow-x: auto`).
4. **Модальные окна на мобильных:**
   - Предпочитать формат шторки (bottom sheet) или аккуратного диалога по центру с отступами от краёв экрана минимум 16px.
   - Обязательно тестировать поведение при открытии клавиатуры на мобильных устройствах.

## 6. Стилизация: Tailwind vs CSS-модули / чистый CSS

В проекте используется гибридный, чётко разграниченный подход:

### Что пишется классами Tailwind:
- Базовая раскладка и flex/grid контейнеры (`flex items-center justify-between gap-3`).
- Отступы и выравнивание (`p-4`, `mb-2`, `space-y-4`).
- Компоновка базовых UI-примитивов с использованием токенов (`bg-surface`, `border-border`, `text-textPrimary`, `rounded-control`).

### Что пишется в CSS / CSS-модулях:
- Специфичная вёрстка страниц (`TodayPage.module.css`, `CalendarPage.css`, `ClientsPage.css` и др.).
- Сложные состояния, медиа-запросы, адаптивные перестроения мобильных сеток.
- Анимации, скроллбары, drag-and-drop стили и кастомные переопределения.

### Правила работы со стилями:
- **Не создавай новые разрозненные CSS-файлы**, если можно использовать модуль страницы или Tailwind-классы.
- Все свойства в CSS-файлах должны ссылаться на токены через `var(--color-...)`, `var(--radius-...)`, `var(--space-...)`.
- **Запрещено использовать `!important`**, кроме редчайших случаев изоляции системного шелла (`crm-shell`) или переопределения сторонних библиотек.

## 7. Соглашения по коду и сохранение бизнес-логики

### Архитектура компонентов
- Один компонент — один файл в `src/components/`.
- Именование компонентов: `PascalCase.jsx` (`TodayPage.jsx`, `VisitMobileCard.jsx`).
- Крупные страницы разбиваются на субкомпоненты (секции, карточки, диалоги), размещаемые рядом со страницей или в подпапках.
- Бизнес-логика, сложные вычисления и запросы выносятся в хуки (`src/hooks/`) или утилиты (`src/utils/`).

### 🔴 Сохранение бизнес-логики (Критично!)
- При любых рефакторингах, правках стилей и улучшении верстки **СТРОГО ЗАПРЕЩЕНО** менять:
  * Поведение данных, структуру объектов визитов/клиентов/услуг/задач.
  * Обработчики событий (`onClick`, `onSubmit`, `onChange`, свайпы).
  * Вызовы API бэкенда (`apiClient`, `fetch`, роуты).
  * Сохранение состояния в `localStorage` или стейт-менеджеры.
- Если задача на UI — меняй **только представление**, не трогая логику!

## 8. Что КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО (Anti-patterns)

1. ❌ **Хардкодить цвета:** Никаких `#ffffff`, `#000000`, `#1a1a1a`, `rgb(...)` в CSS или коде. Только токены `var(--color-...)` или Tailwind-классы.
2. ❌ **Создавать локальные CSS-переменные:** Запрещено определять новые `--my-custom-color` в CSS-файлах страниц. Все токены централизованы в `src/styles/tokens.css`.
3. ❌ **Импортировать `lucide-react` напрямую:** Все иконки вызываются только через `<AppIcon name="..." />` из `src/components/ui/AppIcon.jsx`.
4. ❌ **Использовать нативные `<button>` и `<input>` без UI-компонентов:** Всегда используй `Button`, `IconButton`, `Input`, `Select`, `Textarea`, `Checkbox`, `Switch`.
5. ❌ **Дублировать компоненты:** Не создавай свой кастомный `Badge` или модалку, если есть `src/components/ui/Badge.jsx` и `Dialog.jsx`.
6. ❌ **Ломать одну платформу ради другой:** Нельзя улучшать мобильную версию, ломая десктопную, и наоборот. Всегда проверяй оба вьюпорта.
7. ❌ **Использовать инлайн-стили для оформления:** `style={{ color: '...', padding: '...' }}` запрещены. Инлайн-стили разрешены исключительно для динамической геометрии (расчёт ширины прогресс-бара, CSS-переменная позиции).
8. ❌ **Добавлять сторонние библиотеки стилей:** Никаких новых UI-библиотек (MUI, Chakra, Antd и т.д.) без явного согласования.
9. ❌ **Менять контракты бэкенда:** Не менять формат данных в контроллерах и роутах при задачах на фронтенд.

## 11. Два типа изменений и деплой

| Тип | Пример | Нужен push? |
|-----|--------|-------------|
| Данные CRM (визиты, клиенты, задачи) | Работа в CRM UI | Нет (хранятся в PostgreSQL на Hetzner) |
| Цены и длительности услуг | Изменение в каталоге CRM | Нет (backend автообновляет `site_content`) |
| Код CRM | Новая страница, UI, логика | **Да** → commit → push → Hetzner deploy |
| Контент сайта (тексты, фото) | Изменения на nuarr.pl | **Не в этом репо** → репозиторий `lavandi` |

> После любых успешных изменений кода пользователь ожидает **commit и push** в репозиторий.
